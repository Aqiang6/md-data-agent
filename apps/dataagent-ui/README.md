# Data Agent UI

English | [中文](README.zh.md)

Desktop analysis workspace over the Harness Web session API. The Swiss-style layout keeps session navigation, analysis results, and one execution tree in separate columns, with a minimum width of 1,024 px. Mobile layouts and tests are outside its scope.

## Runtime

Build with `pnpm --filter dataagent-ui build`, prepare the dedicated profile with `pnpm exec tsx scripts/prepare-data-agent-profile.ts`, then launch `pnpm dsh --profile data-agent --no-open`. `start.bat` performs this preparation automatically. The initializer seeds an empty profile once from `dsh-data-agent.patch.yml` and preserves subsequent settings; model configuration stays in the mutable profile user layer, not a command-line overlay. Vite produces the static bundle; only the `dsh` profile supplies authentication, session APIs, tools, and request artifacts. A fresh profile exposes only the bundled official DeepSeek models and selects DeepSeek Flash. It includes no personal database connections or business documents. Configure DEEPSEEK_API_KEY through credential storage or a local .env copied from .env.example; do not commit credentials.

## Analysis History

History and automatic recovery include only root sessions whose recorded preset is `data-agent`. Coding sessions and sessions without a confirmed analysis preset are excluded; missing list hints are resolved from Session projections without activating an Agent. Each record has a separate delete button and inline confirmation with Escape and outside-click dismissal. Deletion reuses the Harness Workspace archive operation: it persistently removes the record from this list and retains logs and report files. The Host refuses active work; failures retain the record and confirmation. Removing the active record selects the next visible record; removing the last shows the empty state. The Workspace follow baseline and archive updates synchronize visibility across windows and restarts without browser-local deletion flags.

Run `node apps/dataagent-ui/tests/analysis-history.web.mjs --live` after building to check real GLM activity protection, confirmed deletion, failure retention, cross-window updates, restart persistence and four desktop widths. Tests use isolated homes and newly created records, not user analyses.

## Models And API

The composer displays the model used by the latest actual request and the model selected for the next request separately. Both come from the original Harness `modelSelection` projection; selection uses `session/selectModel` and its existing durable event. A running request retains its recorded model. Switching updates subsequent requests and asks Harness to save the default for new analyses; historical sessions retain their own selection. Reasoning choices appear only when the exact model advertises them. Provider catalogs refresh after changes, on focus and periodically; failures remain visible.

The sidebar's Models & API page reuses `llm-pi-ai`, model discovery, revision-checked settings mutations and write-only credentials. Custom connections accept OpenAI Chat Completions, OpenAI Responses or Anthropic Messages, Base URL, optional key, model IDs, names, token capacities and image capability. Discovery returns candidates for explicit adoption; manual IDs also work. Saving a connection does not select it. Fields absent from the editor, including compatibility switches and headers, remain intact. API keys stay in form memory until sent to Host credential storage and never appear in settings reads or the Session trace. A failed credential write retries only the credential; stale configuration requires reopening the editor. Removing a user-created connection keeps credentials and cannot remove composition-owned routes. Home patches and command-line overrides remain authoritative and may refuse settings writes.

Run `node apps/dataagent-ui/tests/models.web.mjs` after building for the keyless real-profile browser smoke; `--live` additionally calls the official DeepSeek endpoint using a locally configured key. Each run has isolated homes, a loopback provider, desktop screenshots, video and trajectory output under `.playwright-mcp`.

## Execution And Results

The execution panel folds persisted Session events, follows new events, and backfills gaps by sequence. A workflow run's recorded `callId` locates its tool node; expanding a member follows its actual child session. Historical runs without the identifier remain separate. Request details read immutable harness snapshots, not provider HTTP internals or hidden reasoning. Prompt, context, available tools, request information and original JSON load in full when selected, without a paging or expansion action. Tools include a localized purpose table for the recorded list above their unchanged definitions; unknown tools show their recorded description. All sections offer full downloads and a full-width view. JSON uses one scrolling region without nested code-block height limits; Markdown views do not load images embedded in prompt examples. Late responses cannot overwrite another selected section. Ordinary analysis omits multi-agent orchestration; the [preset configuration](../../packages/experimental/data-agent/README.md#use-this-package) can explicitly enable it without changing historical trees.

Query tables distinguish previews from complete results. Report links use the authenticated artifact endpoint, and HTML previews use a sandboxed iframe. Clarification answers enter the ordinary tool-result log. The source workspace connects MySQL and selects enabled databases and a default database per analysis. Every table in an enabled database is available; the table list supports inspection and filtering, with no enablement controls. Its Schema and Business knowledge libraries use the same multi-file MD management: filtering, individual reading/download, enablement, version-checked replacement and confirmed removal. Configured references can be disabled; uploaded files can also be replaced or removed. Table refresh reads live metadata without creating documents. Connection passwords stay in form memory until submitted to credential storage; public catalog responses contain no passwords or private URLs. See the [domain package](../../packages/experimental/data-agent/README.md#use-this-package) for permissions, creation, scope and upload semantics.

Without an analysis, choosing a source from the home list or top selector creates one analysis and saves that source as its default database. Source management also creates a missing analysis. Creation disables these entries and the New analysis button to prevent duplicate records; failures leave the entries available for retry. An existing analysis receives the selection directly.

Completed answers offer a report-format picker (Markdown, HTML or PDF) and Generate report. Generation requires an explicit click and sends a normal logged follow-up for the selected analysis turn; it does not clear the composer draft. Active analysis disables these controls, and failed sends retain the answer and format for retry. Terminal evidence sections are hidden only in the displayed answer, including historical replies; original Session events and execution details remain unchanged. Inline references, code examples and later answer sections remain visible.

The default analysis preset uses database SQL rather than dataset import, post-query operators or standalone chart tools; see the [domain configuration](../../packages/experimental/data-agent/README.md#use-this-package). Historical calls remain readable, and frontend query charts remain available. Dataset file upload and report editing have no dedicated view. Machine-local databases, business documents, benchmark files and browser output are excluded by the root .gitignore. Official benchmark runs are maintained outside this checkout.

Run `node apps/dataagent-ui/tests/knowledge.web.mjs --live` after building to check source selection from an empty home, creation failure recovery, multi-file uploads, item operations, reload recovery, railway reference discovery, authenticated downloads and four desktop widths, then verify real GLM document reads. The run isolates profile and evidence storage; it does not modify business data.
